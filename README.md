# Programming Course PrairieLearn

Дополнение **1.1** к Course Core **1.0** для заданий PrairieLearn с внешней проверкой проекта и декларативной политики контрольной. Упражнение содержит путь к проекту; расширение добавляет `extensions.prairielearn.grading: external` в нормализованную модель Course Core. Описания упражнений версии 1.0 остаются совместимыми.

Рабочий каталог должен находиться в пути без пробелов: это ограничение разбора проектных hooks в Quarto 1.10/1.11. Кириллица допустима.

## Установка

```sh
quarto add AfonenkoA/programming-course-core-specification@v1.0.0
quarto add AfonenkoA/programming-course-prairielearn-specification
```

В `_quarto.yml`:

```yaml
course:
  schema: "1.0"
  id: programming
  validate: true
filters: [course-core, course-prairielearn]
```

Требования: Quarto ≥ 1.10 и CUE ≥ 0.17. Python, Node.js и отдельный Deno для инструментов не нужны.

## Задание

````qmd
:::: {#exr-clamp target="prairielearn" project="/projects/clamp"}
## Ограничение диапазона

Реализуйте функцию, ограничивающую число заданным диапазоном.
::::
````

`project` обязателен и указывает существующий каталог от корня проекта Quarto. Первый блок упражнения — заголовок. Обычные подзаголовки допустимы. В состав лабораторной, контрольной или экзамена задание включается штатным контейнером `.assessment-items` ядра.

## Политика контрольной

Необязательное поле `assessment.prairielearn` описывает число попыток на каждое
задание, число полностью выполненных заданий для зачёта и метку назначения
варианта студенту:

````qmd
---
assessment:
  kind: test
  prairielearn:
    attempts: 3
    pass:
      at-least: 2
    assignment:
      student-label: referat-s1-01
---

# Защита реферата {#sec-referat-s1-01}

::: {.assessment-items}
1. @exr-experiment
2. @exr-tests
3. @exr-implementation
:::
````

Три упражнения должны быть определены в выбранных документах курса с
`target="prairielearn"`. Количество заданий задаётся списком; профиль не
фиксирует его равным трём. `attempts` и `pass.at-least` — положительные целые
числа; порог не может превышать длину списка. Метка начинается с латинской
строчной буквы и содержит только строчные буквы, цифры и дефисы. Все три поля
обязательны, если присутствует `assessment.prairielearn`; неизвестные поля
отклоняются. Обычные занятия без этого раздела сохраняют прежнее поведение.

Метаданные сохраняются в
`course.assessments[].extensions.prairielearn`. Они не назначают метки
пользователям сервера: преподаватель выбирает или подтверждает тему студента
и назначает соответствующую метку отдельно. Одна метка может применяться к
нескольким контрольным, например основной защите и пересдаче. Проверка
реального состава группы и правил доступа относится к развёртыванию курса.

Будущий компилятор может отобразить приведённую политику на PrairieLearn
Exam с равным весом вопросов, `bestQuestions: 2` и шкалой попыток
`points: [1, 1, 1]` у каждого вопроса. Полный результат такой контрольной
означает два полностью выполненных задания; ошибки в пределах трёх попыток
не уменьшают доступный балл. Это **контракт авторских данных**, а не
реализованный экспорт: расширение не создаёт `infoAssessment.json`, правила
доступа, пользователей или готовый курс PrairieLearn.

## Пример

```sh
cd examples/course
quarto add AfonenkoA/programming-course-core-specification@v1.0.0
quarto add ../..
quarto render
quarto preview
```

`quarto add ../..` устанавливает текущее расширение из корня этого репозитория. Для локального ядра замените команду установки с GitHub на `quarto add ../../../programming-course-core-specification`, если репозитории расположены рядом. Можно указать любой другой путь к ядру; имя рабочего каталога не используется кодом расширения.

Пример содержит упражнение `clamp`, Java-заготовку студента, авторскую реализацию и лабораторную. Java не запускается при сборке книги. Облачные ВМ и каталог ссылок этому примеру не нужны.

Схема поставляется в `_extensions/course-prairielearn/spec/prairielearn.cue`. Расширение проверяет профиль авторских заданий. Генерация PrairieLearn `info.json`, UUID, контейнеров grader, `results.json` и выполнение Java относятся к отдельному компилятору. Идентичность задания задаётся парой `course.id + exercise.id`, независимо от расположения QMD.

## Проверка разработки

Из корня репозитория с установленными Quarto и CUE:

```sh
quarto run tests/check.ts /absolute/path/to/course-core
```

Аргумент указывает каталог установленного расширения `course-core`, в котором
находятся `_extension.yml` и `spec/core.cue`. Проверка рендерит временный курс
штатными расширениями, проверяет извлечённую политику, обратную совместимость
и отклонение неверных параметров схемой. Команда не требует отдельного Deno
и удаляет временные файлы после завершения. При необходимости пути к
исполняемым файлам задаются переменными `QUARTO` и `CUE`.

## Хранение в Git

Коммитьте исходники расширения в корневом `_extensions/`, спецификации, QMD, ресурсы и `.gitignore`. Установленные копии в `examples/**/_extensions/` и результаты сборки примеров исключены из Git. После изменения расширения повторите `quarto add ../..` из примера, чтобы обновить его копию.

Адрес `AfonenkoA/...` в инструкции — источник установки пакета. Расширение не обращается к этому адресу при сборке. Для форка или локальной копии изменяется только команда `quarto add`.
