# Задания курса в PrairieLearn

Расширение `course-prairielearn` описывает проектные задания с внешней проверкой и правила проведения контрольных работ. Оно дополняет текущую спецификацию Course Core: извлекает авторские данные из Quarto, добавляет их в общую модель курса и проверяет правилами CUE.

Ядро, адаптер и курс обновляются совместно. Версия схемы в YAML не указывается, старые формы описания не поддерживаются. Номер в `_extension.yml` служит метаданными пакета. Экспорт в PrairieLearn и запуск проверки в состав расширения не входят.

## Подключение

Нужны актуальные Quarto, CUE и ядро Course Core. CI проверяет каналы Quarto `release` и `pre-release`. Python, Node.js и отдельная установка Deno не требуются. Рабочий путь должен быть без пробелов из-за разбора команд сборки в Quarto; кириллица допустима.

```sh
quarto add AfonenkoA/programming-course-core-specification
quarto add AfonenkoA/programming-course-prairielearn-specification
```

В `_quarto.yml` задают общие правила контрольных:

```yaml
course:
  id: programming
  validate: true
filters: [course-core, course-prairielearn]
prairielearn:
  assessment-defaults:
    attempts: 3
    pass:
      at-least: 2
    assignment:
      mode: assessment-id
```

Ядро должно предшествовать адаптеру в списке фильтров. Раздел `prairielearn.assessment-defaults` действует только на контрольные, которые явно подключили его через `assessment.prairielearn`.

## Задание и контрольная работа

````qmd
---
assessment:
  kind: test
  prairielearn:
    pass:
      at-least: 1
---
````

Первый элемент задания — заголовок. Атрибут `project` указывает существующий каталог от корня проекта Quarto; глубина вложенности произвольна. Условие хранится в QMD, а заметки `.grading-notes` ядро выделяет в отдельное поле модели. Вручную создавать `question.html` не требуется.

В примере одна задача, поэтому локальный порог равен единице. Число попыток и способ назначения наследуются из общих настроек. Пустая карта `assessment.prairielearn: {}` подключает все общие значения. Локальные поля переопределяют их; локальная `assignment` заменяет общую стратегию целиком. Все задания такой контрольной должны иметь `target="prairielearn"`.

Класс `.when-full` относится к Course Core и скрывает содержимое в студенческом представлении. Для его использования в профилях задают `course.view: student` и `course.view: full`. Скрытые задания и заметки удаляются до извлечения студенческой модели.

Режим `assignment.mode: assessment-id` создаёт устойчивую метку из `course.id` и идентификатора контрольной. Перемещение страницы не меняет метку. Вместо вычисления можно явно задать `assignment.student-label`, например общую метку для основной защиты и пересдачи. Сам адаптер не назначает метки студентам на сервере.

Публичную демонстрацию можно оформить с `target="manual"`: она останется в общей модели, но не получит параметры внешней проверки PrairieLearn. Полные правила, границы видимости и требования к будущему компилятору описаны в [спецификации](docs/authoring.md).

## Пример и проверка

```sh
cd examples/course
quarto add AfonenkoA/programming-course-core-specification
quarto add ../..
quarto render --profile student
quarto render --profile full
```

Пример включает открытое задание, демонстрацию `manual`, обычное занятие и закрытую контрольную с тремя заданиями. Вместо адреса GitHub можно указать локальный репозиторий ядра. После изменения адаптера повторите `quarto add ../..`, чтобы обновить установленную копию.

Из корня репозитория запускается интеграционная проверка:

```sh
quarto run tests/check.ts ../programming-course-core-specification
```

Аргумент — корень репозитория Course Core. Проверка устанавливает расширения во временный проект, проверяет извлечение данных из QMD, правила CUE, наследование настроек, устойчивость меток и раздельную сборку `student`/`full`. Ошибочные настройки должны отклоняться; закрытые условия и критерии не должны попадать в студенческую модель или HTML. Пути к программам можно задать через `QUARTO` и `CUE`.

GitHub Actions выполняет эти проверки и собирает пример для PR, изменений в основной ветке, по запросу и еженедельно в каналах Quarto `release` и `pre-release`. Коммит ядра закреплён в `.github/workflows/ci.yml` и обновляется вместе с адаптером. Это обеспечивает воспроизводимость CI без выбора версии схемы в конфигурации курса.

В Git хранятся исходники, правила CUE, QMD и авторские ресурсы. Установленные зависимости примеров и результаты сборки исключены. Адрес репозитория участвует только в установке и не используется при сборке.
