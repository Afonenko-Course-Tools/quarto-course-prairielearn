# Задания курса в PrairieLearn

Расширение `course-prairielearn` описывает проектные задания с внешней проверкой и правила проведения контрольных работ. Оно дополняет текущую спецификацию ядра курса: извлекает авторские данные из Quarto, добавляет их в общую модель курса и проверяет правилами CUE.

Ядро, адаптер и курс обновляются совместно. Версия схемы в YAML не указывается, старые формы описания не поддерживаются. Номер в `_extension.yml` служит метаданными пакета. Текущий контракт явно содержит `export_implemented: false`: создание native package PrairieLearn и запуск grader пока не реализованы.

## Подключение

Обычный native render использует Quarto 1.10.18/1.11.5, CUE и ядро курса. CI проверяет Quarto 1.10.18 и 1.11.5. Python, Node.js и отдельная установка Deno не требуются. Рабочий путь должен быть без пробелов из-за разбора команд сборки в Quarto; кириллица допустима.

```sh
quarto add Afonenko-Course-Tools/quarto-course
quarto add Afonenko-Course-Tools/quarto-course-prairielearn
```

В `_quarto.yml` задают общие правила контрольных:

```yaml
project:
  pre-render:
    - _extensions/Afonenko-Course-Tools/course-core/entrypoints/pre.ts
  post-render: _extensions/Afonenko-Course-Tools/course-core/entrypoints/post.ts
course:
  id: programming
  validate: true
  adapters: [prairielearn]
filters: [course-core, course-prairielearn]
prairielearn:
  assessment-defaults:
    attempts: 3
    pass:
      at-least: 2
    assignment:
      mode: assessment-id
```

Ядро должно предшествовать адаптеру в списке фильтров. `course.adapters` явно включает контракт; установка пакета сама по себе его не активирует. Пути к обработчикам указывают установленный каталог ядра; при локальной установке это `_extensions/course-core/`. Раздел `prairielearn.assessment-defaults` действует только на контрольные, которые явно подключили его через `assessment.prairielearn`.

## Задание и контрольная работа

````qmd
---
assessment:
  kind: test
  prairielearn:
    pass:
      at-least: 1
---

::::: {.when-full}

:::: {#exr-decoding-experiment course-role="control" difficulty="introductory" target="prairielearn" project="/decoding/projects/experiment"}
## Анализ декодирования

Условие задания с точным описанием входных и выходных данных.

::: {.grading-notes}
Критерии проверки и ограничения закрытых тестов.
:::
::::

::: {.assessment-items}
1. @exr-decoding-experiment
:::

:::::
````

Первый элемент задания — заголовок. Атрибут `project` указывает существующий каталог от корня проекта Quarto; глубина вложенности произвольна. Условие хранится в QMD, а заметки `.grading-notes` ядро выделяет в отдельное поле модели. Для этой авторской разметки `question.html` не требуется; его генерация, `info.json`, UUID и конфигурация grader относятся к будущему экспортёру.

В примере одна задача, поэтому локальный порог равен единице. Число попыток и способ назначения наследуются из общих настроек. Пустая карта `assessment.prairielearn: {}` подключает все общие значения. Локальные поля переопределяют их; локальная `assignment` заменяет общую стратегию целиком. Все задания такой контрольной должны иметь `target="prairielearn"`.

Класс `.when-full` относится к ядру курса и скрывает содержимое в студенческом представлении. Для его использования в профилях задают `course.view: student` и `course.view: full`. Скрытые задания и заметки удаляются до извлечения студенческой модели.

Режим `assignment.mode: assessment-id` создаёт устойчивую метку из `course.id` и идентификатора контрольной. Перемещение страницы не меняет метку. Вместо вычисления можно явно задать `assignment.student-label`, например общую метку для основной защиты и пересдачи. Сам адаптер не назначает метки студентам на сервере.

Публичную демонстрацию можно оформить с `target="manual"`: она останется в общей модели, но не получит параметры внешней проверки PrairieLearn. Полные правила, границы видимости и требования к будущему компилятору описаны в [спецификации](docs/authoring.md).

## Java-проекты и граница экспорта

[Открытое задание](examples/course/tasks/index.qmd) использует Java-класс
`Clamp`; рядом находятся [стартовый файл](examples/course/projects/clamp/student/Clamp.java)
и [авторская реализация](examples/course/projects/clamp/reference/Clamp.java).
[Контрольная](examples/course/controls/ranges.qmd) показывает три вида авторской
работы: исследование граничных случаев, написание теста и реализацию метода.
Они используют одну декларацию внешней проверки; адаптер не компилирует Java
и не запускает её тесты.

| Результат | Возможность расширения |
|---|---|
| Модель курса и HTML student/full | Извлечение через Core, CUE-проверка и нативный HTML render |
| Фрагменты JSON адаптера | Внутренние данные общей модели, не `info.json` PrairieLearn |
| Стартовые файлы для студента | Отдельный Download с явным выбором ресурсов; `project` не разрешает публиковать весь каталог |
| PL native package и разделение client/server assets | Требуется реализация экспортёра |
| Java grader, контейнер, лимиты и обработка submission | Требуется реализация среды проверки |
| Загрузка курса, назначение доступа, попытки и оценки | Требуются развёртывание и проверка на целевой PrairieLearn |

Наличие общего Body API с типами ответов в Core не добавляет их автоматически
в этот адаптер. Правила будущего компилятора и разделение ученических,
преподавательских и проверяющих материалов описаны в
[спецификации](docs/authoring.md).

## Пример и проверка

Курс собирают обычной командой Quarto. `render.ts` — короткий пример вызывающего кода, который проверяет код завершения native процесса.

```sh
cd examples/course
quarto add ../../../quarto-course
quarto add ../..
quarto run render.ts student
quarto run render.ts full
```

Пример включает открытое задание, демонстрацию `manual`, обычное занятие и закрытую контрольную с тремя заданиями. Пример ожидает соседний локальный репозиторий `quarto-course`; при установке ядра из GitHub укажите в `_quarto.yml` путь с каталогом владельца. После изменения адаптера повторите `quarto add ../..`, чтобы обновить установленную копию.

Из корня репозитория запускается интеграционная проверка:

```sh
quarto run tests/check.ts ../quarto-course
```

Аргумент — корень репозитория ядра курса. Проверка устанавливает расширения во временный проект, проверяет извлечение данных из QMD, правила CUE, наследование настроек, устойчивость меток и раздельную сборку `student`/`full`. Ошибочные настройки должны отклоняться; закрытые условия и критерии не должны попадать в студенческую модель или HTML. Пути к программам можно задать через `QUARTO` и `CUE`.

GitHub Actions выполняет эти проверки и собирает пример для PR, изменений в основной ветке, по запросу и еженедельно в каналах Quarto `release` и `pre-release`. CI получает согласованный коммит `Afonenko-Course-Tools/quarto-course` и проверяет согласованность текущих контрактов без выбора версии схемы в конфигурации курса.

В Git хранятся исходники, правила CUE, QMD и авторские ресурсы. Установленные зависимости примеров и результаты сборки исключены. Адрес репозитория участвует только в установке и не используется при сборке.

## Единый словарь и архитектура

`contract.json` — источник идентификатора адаптера и повторно используемых
допустимых значений. Lua читает этот файл непосредственно; объявления
перечислений в CUE создаёт `quarto run tools/sync-contract.ts`. Проверка
`quarto run tools/sync-contract.ts --check` обнаруживает рассогласование и
выполняется в CI. Остальные ограничения модели задаются только в CUE.
Генератор словаря нужен сопровождающему расширения; автор курса получает
готовые файлы и не запускает его.

Модули извлечения не выполняют команды задания и не создают файлов целевой
платформы. Фильтр отвечает за обход документа и запись фрагмента, отдельные
модули — за преобразование разметки, схема CUE — за ограничения модели.

## Текущий авторский маршрут Core

Каждое `exr-*` явно задаёт `course-role` (`demonstration`, `discussion`,
`independent-study` или `control`) и `difficulty`; ближайший заголовок темы
имеет явно написанный ID `sec-*`. В книге для этого нужен отдельный заголовок
внутри главы: заголовок самой главы Quarto переносит в metadata. Примеры
используют `difficulty="introductory"`.
Объявления `exm-*` остаются обычными учебными примерами и не создают Exercise.
Решение демонстрации открыто, если его родитель открыт; контрольные задания,
ключи и обычные решения не появляются в студенческом представлении.

В конфигурации нужны профили `student`/`full` с соответствующим `course.view`
и отдельными `project.output-dir`. Ядро проверяет исходный AST и локальные
правила явно включённых адаптеров до удаления закрытых блоков. Затем адаптер
сохраняет только видимые факты документа. После успешной native команды явный вызывающий код проверяет CUE всей
модели, включая ссылки на задания из других документов.

```sh
quarto render --profile student
quarto render --profile full
quarto run _extensions/course-core/entrypoints/check.ts . full
quarto preview --profile student
```

Sidecar документа содержит source, view, format и profiles. Pre-hook начинает
новый набор результатов; post-hook использует только документы текущего native
процесса. Сохранённые фрагменты других профилей не подтверждают успешную сборку.
Потребитель полной модели должен также проверить успешное завершение команды:
запись DocumentResult сама по себе не подтверждает работу writer и поздних hooks.
Для выбранного документа cross-document правила откладываются до явной полной
сборки. Установка пакета без `course.adapters` не объявляет его target активным.

Проверяемый commit Core закреплён в [.github/workflows/ci.yml](.github/workflows/ci.yml); интеграционные
тесты устанавливают этот пакет целиком и проверяют декларации. Это не доставка
на платформу: экспорт/импорт, отправка студенческих работ и синхронизация оценок
не реализованы данным адаптером.
