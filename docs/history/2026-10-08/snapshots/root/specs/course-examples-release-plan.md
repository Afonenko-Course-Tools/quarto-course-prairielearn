# Демонстрационные курсы ресурсы и артефакты

Общий план производителей демонстраций. Исходники находятся в репозиториях расширений; одна группа — самостоятельный небольшой курс с общими ресурсами и несколькими сценариями. Этот документ задаёт общие требования к группам и их выпускам; сборка сайта относится к шаблону.

Общие решения, ограничения и порядок выпуска: [межрепозиторный план](course-change-plan.md). Перед изменением поведения — анализ актуальной архитектуры и необходимый рефакторинг. Поддерживается только актуальный авторский формат без обратной совместимости; публичные функции Quarto переиспользуются. Код, спецификации, README и примеры обновляются согласованно в соответствующем PR.

### Этап 4 Общие ресурсы и переносимость

- [ ] Оставить общую библиографию в корне каждого курса, явно подключать её в компонентах.
- [ ] Хранить в папке примера корень курса и необходимые ресурсы: библиографию, CSL при его использовании, includes, изображения, проекты заданий и конфигурации.
- [ ] Добавить штатные ссылки Quarto на папку примера и исходные `.qmd` в GitHub.
- [ ] Проверять возможности AST при экспорте условий с цитатами, сносками и другими конструкциями; поддержка HTML сама по себе не гарантирует переносимость в Print или LMS.

Проверки результата: папка примера получена из GitHub и проверена в чистом каталоге; разрешаются документированные зависимости и локальные пути; общий источник виден во всех компонентах; исходный `.qmd` соответствует показанной версии. Собственная упаковка курса не выполняется.

### Этап 6 Курсы примеры и языковые среды

- [ ] Подготовить группы демонстраций основ курса, представления материалов и платформенных адаптеров.
- [ ] Показать отдельные контрольные файлы, student/full-списки, общий контрольный набор и отдельные QMD вариантов. Для экспорта требовать минимум, достаточный для демонстрации модели; создание и настройка тестов Moodle средствами системы не входят в обещание экспортёра.
- [ ] Использовать `full` по умолчанию в демонстрационных проектах; не переносить на полноценные курсы их намеренно публичную политику решений и комментариев.
- [ ] Включить минимальный составной пример, презентацию, обычную PDF-раздатку и раздатку из банка заданий, PrairieLearn, Cloud и Moodle. Не наполнять демонстрации полноценным учебным курсом.
- [ ] Каждую группу оформить как один небольшой демонстрационный курс с несколькими сценариями. Общие задания и ресурсы хранить внутри папки группы, без зависимостей от соседних учебных папок. Ссылка на исходники ведёт на всю группу; её получение и установка расширений документируются отдельно.
- [ ] Определить минимальную матрицу сочетаний расширений и языковых сред для первого выпуска.
- [ ] У каждого исполняемого примера определить собственную сборку и проверки. Использовать штатные файлы Gradle, CMake, Python, Julia и R.
- [ ] Разделить задачи CI по средам; каждый job устанавливает только свои инструменты и нужные зависимости Quarto.
- [ ] При проверке расширения собирать пример с установленной поставкой кандидата; при публикации закреплять совместимые версии зависимостей.

Проверки результата: Java-проект действительно проходит Gradle; C++ — выбранную сборку CMake и проверки; Python, Julia и R — свои исполняемые примеры. Наличие файлов сборки и успешный HTML недостаточны для этих утверждений. Выполнение виртуальной машины и обмен с реальной LMS подтверждаются отдельно, если включены в обещание конкретного примера.

## Выпуск результатов

Релизные артефакты собираются из проверенного слитого коммита и закреплённых выпусков зависимостей. HTML, ресурсы, QRC, PDF и ссылки на исходники относятся к одной ревизии и проекции. Все assets проверяются и прикладываются до публикации неизменяемого Release; допускается отдельный выпуск демонстраций в том же репозитории. Указатели потребителя содержат точные URL, без автоматического разрешения версий.

Получение готовых результатов и локальная проверка сайта: [план документации](../quarto-template-course/docs/plans/course-documentation-plan.md).
