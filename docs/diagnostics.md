# Диагностика PrairieLearn

Собственные сообщения расширения содержат ID, компонент `course-prairielearn`,
русское объяснение и доступный контекст: `source` — входной файл,
`id` — вопрос или работа, `field` — проверяемое поле. Строка «связано» указывает
работу, вопрос или ресурс, а «подсказка» описывает исправление.
Контекст не добавляет обязательных полей в модель курса или Body-пакет.

| ID | Что проверяется | Что сделать |
|---|---|---|
| `PL001_externalAssessmentMembers` | В явно подключённую работу PrairieLearn входят только задания с `target="prairielearn"`. | Проверьте состав `.task-items` и `target` указанных заданий. |
| `ADAPTER` | Публичный Body-пакет и состав одной работы, явные привязки вопросов, внешний проверяющий инструмент, поддерживаемое условие, ресурсы и файлы поставки. | Найдите вопрос и поле в контексте сообщения; исправьте условие, проект или `binding.questions.<id>`. |
| `PL.INPUT_INVALID` | Аргументы явного экспорта, наличие установленного Core и чтение JSON-привязки. | Укажите корень курса, книгу, ID работы, привязку и новый каталог результата; установите совместимый Core в книгу. |
| `PL.ASSESSMENT_INVALID` | Форма настроек работы и общих настроек, стратегия назначения и порог относительно списка заданий. | Проверьте `assessment.prairielearn`, `prairielearn.assessment-defaults` и `.task-items`. |
| `PL.PROJECT_INVALID` | Путь проекта и существующий каталог внутри выбранной книги. | Укажите путь от корня книги, например `/projects/clamp`. |
| `PL.FILTER_ORDER` | Core обрабатывает документ до адаптера. | Укажите `filters: [course-core, course-prairielearn]`. |
| `PL.CONTRACT_INVALID` | Доступен установленный контракт адаптера. | Переустановите расширение целиком. |
| `PL.NATIVE_INVALID` | Согласованы представление, каталог, указатель и профили native-сборки. | Повторите сборку с согласованными Core и адаптером; сохраните исходное сообщение при обращении к сопровождающему. |

Правила количества попыток, порога и назначения проверяет CUE. Его именованные
правила и исходный вывод сохраняются. Адаптер добавляет исходный QMD и ID работы,
но не заменяет сообщение CUE собственным семантическим ID. Позиции в
`candidate.json` или файле `.cue` относятся к этим файлам; они не являются
номерами строк исходного QMD.

Отказ Core также сохраняет исходный ID, сообщение и причину. Например,
неизвестного участника работы обнаруживает Core; адаптер не превращает такой
отказ в `ADAPTER`. При ссылке на задание в другом документе его источник может
появиться только после сбора модели Core. Локальная проверка документа использует
только известные ей факты.

Отказ Quarto/Pandoc содержит инструмент, код выхода, stdout, stderr и исходную
причину. Это ошибка внешней команды, без нового семантического ID расширения.
Исходный вывод показывается один раз. Внешние ошибки Java/Gradle остаются выводом
Java/Gradle. CLI кратко выводит известные собственные и внешние отказы;
неизвестное внутреннее исключение сохраняет stack для расследования.

Экспорт сначала подготавливает публичное условие и файлы, затем записывает
временный каталог рядом с результатом и переносит его в новый каталог поставки.
При отказе временный каталог удаляется. Уже существующий результат не
перезаписывается. Исправьте причину и повторите экспорт в новый каталог.

См. [правила авторства](authoring.md), [явный экспорт](../README.md#явный-экспорт-вопросов)
и [Java/Gradle-группу](../examples/java-gradle/README.md).
