# Диагностика PrairieLearn

Собственные сообщения расширения содержат ID, компонент `course-prairielearn`,
русское объяснение и доступный контекст: `source` — входной файл,
`id` — вопрос или работа, `field` — проверяемое поле. Строка «связано» указывает
работу, вопрос или ресурс, а «подсказка» описывает исправление.
Контекст не добавляет обязательных полей в модель курса или Body-пакет.

| ID | Что проверяется | Что сделать |
|---|---|---|
| `PL001_externalAssessmentMembers` | В явно подключённую работу PrairieLearn входят только задания с `target="prairielearn"`. | Проверьте состав `.task-items` и `target` указанных заданий. |
| `ADAPTER` | Публичный Body-пакет и состав одной работы, явные привязки вопросов, внешний проверяющий инструмент, поддерживаемое условие, ресурсы и файлы поставки. | Найдите вопрос и поле в контексте сообщения; исправьте условие, проект или `binding.questions.<id>`. |
| `PL.INPUT_INVALID` | Аргументы явного экспорта, наличие установленного Core и чтение JSON-привязки. | Укажите корень курса, книгу, ID работы, привязку и новый каталог результата; установите совместимый Core в книгу. |
| `PL.ASSESSMENT_INVALID` | Форма настроек работы и общих настроек, стратегия назначения, порог относительно списка заданий и неверный/повторный native UUID. | Проверьте `assessment.prairielearn`, `prairielearn.assessment-defaults` и `.task-items`. |
| `PL.PROJECT_INVALID` | Путь проекта и существующий каталог внутри выбранной книги. | Укажите путь от корня книги, например `/projects/clamp`. |
| `PL.FILTER_ORDER` | Core обрабатывает документ до адаптера. | Укажите `filters: [course-core, course-prairielearn]`. |
| `PL.CONTRACT_INVALID` | Доступен установленный контракт адаптера. | Переустановите расширение целиком. |
| `PL.NATIVE_INVALID` | Согласованы представление, каталог, указатель и профили native-сборки. | Повторите сборку с согласованными Core и адаптером; сохраните исходное сообщение при обращении к сопровождающему. |

Правила попыток, порога, назначения и неизвестные поля проверяет исполняемый TS-контракт владельца.
Диагностика сохраняет исходную причину и конкретный `source/id/field`; путь
в schema issue относится к callback metadata, а не к выдуманной строке QMD.
