# Контексты проектов текущей native-операции

`withNativeProjectPlans` использует публичный
`operation.withProjectContracts(requests, use)`. Запрос содержит `owner`,
`directories`, фактически выбранные `profiles` и `format`. Каталог кодового
проекта передаётся непосредственно; технический QMD не создаётся.

Все контексты и планы student/full создаются и используются внутри callback.
Core читает участвующие YAML один раз за операцию, наследует их в памяти и
возвращает метрики `yamlFileReads`, `directoryLayers`, `sourceBytesRead`.
PL сохраняет фактическую группировку по формату и проверяет соответствие
полученных каталогов запросу. Подмены приватным импортом Core, повторным inspect
или запасным loader нет.

Обычный путь относится к конечному кодовому проекту. Общий путь с `base: config`
относится к объявившему YAML, включая подключённый файл. Адрес `{path, base?}`
заменяется целиком. `build.files` использует тот же договор адреса.

Действительные файлы передаются как `ArtifactFiles`, публичные ресурсы —
`NativeResourceFiles`. Проверка release возвращает функциональные данные;
собственные SHA, origin DTO и свидетельства актуальности удалены. Согласованное
обновление producer и consumers обязательно; старый wire format не поддерживается.
